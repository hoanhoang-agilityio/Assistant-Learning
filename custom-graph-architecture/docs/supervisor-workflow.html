Supervisor Workflow

Revision 2 — user_agent now owns the profile fully through its own tools, hitl_agent is one shared approval gate for both a plan and a profile write, and finalize_turn is gone: nothing exits to end except a blocked input and the supervisor's own FINISH. Nothing here is implemented yet.

What changes vs. today's graph

removed
parse_turn's intent step, merge_profile, check_profile_complete, request_missing_profile_fields, wait_for_user, profile_collection_exhausted — the whole profile pipeline is gone from the graph and lives inside user_agent instead. finalize_turn is also gone: nothing left for it to do once persistence moved to commit_plan / commit_profile_update and the reply is just the last AIMessage in the transcript.
added
supervisor (LLM router, structured output) · user_agent, a real tool-calling agent like coach_agent/qa_agent, with exactly two tools: get_user_profile (read) and update_user_profile — writes immediately when the field is currently unset, and only stages the change (no write) when it would overwrite a value the profile already holds · hitl_agent, one shared interrupt-and-decide node, reached only for that overwrite case · commit_plan / commit_profile_update, the only two nodes in the graph that write an approved change · summarize.
generalized
hitl_review → hitl_agent: same interrupt, same approve/reject/ feedback/retry-cap mechanics, but the payload it shows and the decision it returns are now generic (pending_approval, approval_decision) instead of plan-shaped, so user_agent can reuse it for a profile write.
unchanged
Everything inside the dashed boxes — deterministic_verification, present_plan, notify_fail, verify_faithfulness, qa_fallback — same nodes, same edges, same retry caps as graph.py today; they now exit into summarize instead of finalize_turn.
state
+next, +iteration_count, +summary, +pending_approval, +approval_decision, +approval_feedback, +approval_retry_count. -intent, -extracted_facts, -missing_fields, -revision_fields, -user_info_retry_count, -hitl_decision, -hitl_feedback, -hitl_retry_count, -final_message.

Resolved: when does a profile write need approval

Filling a field that is currently blank — the common case, a first-time missing field user_agent just asked for — writes immediately inside update_user_profile. No interrupt, no extra turn: answering the question is the confirmation. hitl_agent is reached only when the new value would replace one the profile already holds — an actual overwrite, where something could be lost. So coach_agent sees a freshly-supplied missing field on the very next supervisor hop, same turn, no approval round trip; only a correction to an existing value pays for one.
